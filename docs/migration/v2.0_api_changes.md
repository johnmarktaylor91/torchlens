# TorchLens 2.0 API changes

The current TorchLens 2.x surface reserves exactly 116 top-level names in `torchlens.__all__`. Names
outside that budget either moved to a namespace with a deprecation shim, remain
available only from their canonical namespace, or are implemented top-level
helpers that fit inside the public namespace budget.

## Wrapper migrations

## Phase 1b: option classes + canonical vocabulary

Grouped options are now available under `torchlens.options`. Individual kwargs
continue to work for the migration window, but option objects are the preferred
style for new code.

For selective activation capture, the unified predicate surface is now preferred:
`tl.trace(model, x, save=tl.func("relu"))` returns a full `Trace`, while
`tl.record(model, x, save=tl.func("relu"))` returns a sparse `Recording`.
The old `record(keep_op=...)` / `record(keep_module=...)` alias kwargs are removed. Use
`storage=tl.to_disk(path)` to stream predicate-selected payloads to disk.

Backend selection is now explicit when needed: `tl.trace(..., backend=None)` preserves torch eager
default plus MLX module auto-routing, while `backend="torch"` forces the torch backend and fails
early if the model/input does not match. Public backend metadata is exposed on `Trace.backend`,
`Trace.module_identity_mode`, `Trace.param_source`, and neutral record fields such as
`dtype_ref`, `device_ref`, `backend_address`, and `resolver_status`. `tl.record()` remains
torch-only in backend v1.

| Entry point | Old kwarg | New option-class field / canonical kwarg |
|---|---|---|
| `trace` | `layers_to_save` | Prefer `save=...` predicates for one-pass capture; use `capture=CaptureOptions(layers_to_save=...)` only for final-label two-pass selection. |
| `trace` | `keep_unsaved_layers` | No direct equivalent: trace metadata is retained for all operations; use `save=...` or `capture=CaptureOptions(layers_to_save=...)` to control saved payloads. |
| `trace` | `output_device` | `capture=CaptureOptions(output_device=...)` |
| `trace` | `save_function_args` | `capture=CaptureOptions(save_arg_values=...)` |
| `trace` | `save_gradients`, `gradients_to_save`, `save_grads_to`, `keep_grads_in_memory` | `save_grads=...` and `storage=tl.to_disk(...)` |
| `trace` | `random_seed`, `detect_loops` | `capture=CaptureOptions(random_seed=..., recurrence_detection=...)` |
| `trace` | `mark_input_output_distances` | `capture=CaptureOptions(compute_input_output_distances=...)` |
| `trace` | `activation_postfunc` | `save=SaveOptions(activation_transform=...)` |

Before:

```python
log = tl.trace(
    model,
    x,
    layers_to_save=["fc1"],
    activation_postfunc=lambda t: t.detach().cpu(),
    vis_mode="rolled",
    vis_nesting_depth=2,
)
```

After:

```python
log = tl.trace(
    model,
    x,
    capture=tl.options.CaptureOptions(layers_to_save=tl.func("linear")),
    save=tl.options.SaveOptions(activation_transform=lambda t: t.detach().cpu()),
)
log.draw(view="rolled", depth=2)
```

Forward validation:

```python
# Before
import torchlens as tl
ok = tl.validate_forward_pass(model, x, None, 42)

# After
from torchlens.validation import validate_forward_pass
ok = validate_forward_pass(model, x, None, 42)
```

Consolidated validation accepts `backend=None` and dispatches through the same backend registry
as capture. Supported backend/scope pairs return real bools; unsupported capabilities raise typed
backend errors instead of silently skipping.

Backward validation:

```python
# Before
ok = tl.validate_backward_pass(model, x, None, loss_fn)

# After
from torchlens.validation import validate_backward_pass
ok = validate_backward_pass(model, x, None, loss_fn)
```

Saved-activation validation:

```python
# Before
ok = tl.validate_saved_activations(model, x)

# After
ok = tl.validate(model, x, scope="saved")
```

Summary:

```python

```

Forward graph:


Backward graph:

```python
# Before
dot = tl.draw_backward(trace, vis_outpath="backward")

# After

loss = trace[trace.output_layers[0]].out.sum()

```

Intervention spec load:

```python
# Before
spec = tl.load_intervention_spec("run.tlspec")

# After

```

## Phase 1c: exception taxonomy

TorchLens-specific failures now share a compact domain taxonomy under
`torchlens.errors`. Existing exception names remain available for one minor
cycle so current `except OldExceptionName:` blocks keep working.

```python
import torchlens as tl
from torchlens import errors

try:
    log = tl.trace(model, x)
except errors.ConfigurationError:
    handle_bad_options()
except errors.CompatibilityError:
    handle_unsupported_model_or_storage()
except errors.CaptureError:
    handle_capture_failure()
except errors.ValidationError:
    handle_validation_failure()
except errors.InterventionError:
    handle_intervention_failure()
```

Every TorchLens exception and warning exposes the structured payload fields
`file_path`, `line_no`, `affected_sites`, and `severity`.
